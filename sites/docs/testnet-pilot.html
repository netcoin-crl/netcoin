M1 pilot plan

Run the two-week tester loop without losing evidence.

Start with 5 testers, expand only after P0/P1 blockers stay quiet, and record every wallet -> faucet -> explorer -> status friction point safely.

Open tester pathOpen feedback intakeCheck Status

Do not skip preflight

Run make m1-rc-check and make m1-rc-strict in the real checkout before inviting testers. This page does not claim mainnet readiness.

entry criteria

Invite testers only after these pass

  • Source gate: make m1-rc-check passes.
  • Strict gate: make m1-rc-strict is run locally and failures are fixed or documented.
  • Live smoke: Wallet, Faucet, Explorer, and Status load through Host-header checks.
  • Roles: incident owner, scribe, operator, and communicator are assigned.
  • Intake: feedback log is ready and no tester is asked for secrets.

Cohort

  • Start with 5 testers.
  • Expand to 10 only after 48 hours with no P0/P1 blockers (expand to 10 only when safe).
  • Cover iPhone Safari, Android Chrome, desktop Chrome, Firefox, and Safari or Edge.

Required loop

  1. Create wallet.
  2. Claim Faucet NET.
  3. Verify in Explorer.
  4. Send a tiny payment.
  5. Lock and unlock.
  6. Check Status if slow.
  7. File feedback.

Stop conditions

  • Secret exposure.
  • Wallet create/unlock/send regression.
  • Faucet abuse or cooldown bypass.
  • Dangerously stale Explorer or Status data.
  • Any SEV-1 incident.
